# 视听语言与创意质量

本参考只提供给创意策略或已选方案制作 subagent。它把短剧广告的视听设计、玩法融合和质量审核压缩成可执行规则；不替代原剧证据、商品事实、用户确认、参考图审核或分镜编译器，也不授权图片、视频、上传或重试。

完整结构化规则位于 `audiovisual-quality-matrix.json`。不要整份加载；先按当前阶段查询，再只消费命中的记录：

```bash
NOVVY_PYTHON_BIN="$("$SKILL_DIR/scripts/novvy_python.sh")"
"$NOVVY_PYTHON_BIN" "$SKILL_DIR/scripts/query_audiovisual_quality.py" summary
"$NOVVY_PYTHON_BIN" "$SKILL_DIR/scripts/query_audiovisual_quality.py" quality --module '创意方案' --limit 0
"$NOVVY_PYTHON_BIN" "$SKILL_DIR/scripts/query_audiovisual_quality.py" quality --field '推近压迫镜头 Push In Tension Shot'
"$NOVVY_PYTHON_BIN" "$SKILL_DIR/scripts/query_audiovisual_quality.py" director --name '大卫·芬奇'
```

## 规则库摘要

- 来源共有 190 条逻辑记录，规范化后是 189 条可调用记录。
- 质量字段 129 条，覆盖剧集理解、创意方案、构图、机位、运镜、剪辑、音频、特效/UI、玩法融合、质量管控和生产流程。
- 导演来源记录 61 条，其中 1 条重复；规范化为 60 位唯一导演。45 位是完整记录，15 位只有摘要；原材料声称 65 位，缺少的 5 位不得补造。
- 规范化只修复列错位、显式去重或把缺失值标成 `not_provided`。原剧和商品事实仍以当前工作流证据为准。

## 按阶段读取

| 阶段 | 应查询模块 | 使用目的 |
|---|---|---|
| 创意候选 | `创意方案`、`玩法融合`、`质量管控` | 检查剧情承接、单一核心玩法动词、悬念缺口、转化路径与硬门风险 |
| 视听方向 | 与方案相关的 `构图-基础`、`机位角度-基础`、运镜模块、`剪辑-风格` | 把情绪和叙事任务编译成可观察镜头参数 |
| 声音设计 | `音频体系` | 规划声桥、人声、环境、拟音、BGM、UI 音效时序和动态范围 |
| UI/VFX | `特效UI` | 让效果绑定事件，确保 UI 在实体动作和世界结果之后出现 |
| 制作审核 | `质量管控`、`生产流程` | 先判硬门，再做 CQ 0-3 分级；明确人工确认与下一步 |
| 风格参考 | 单条 `director` 记录 | 只提取 2-4 个可观察元素，不复制作品、角色、剧情或具体镜头 |

查询应以当前方案真实需要为限。不要为了显示专业性堆叠运镜、特效或导演；同一镜头优先选择一个主要镜头动作和一个清晰的叙事目的。

## 创意与玩法合同

1. 原剧优先：先延续人物目标、关系、情绪、表演、空间与影调，再承载游戏动作。没有全剧或重点集证据的结论写 `unknown`，不得虚构。
2. 世界动作优先：角色或观众先产生诉求并执行实体动作，世界先给出结果，UI/VFX 和反馈音再强化它。不得让 UI 代替因果。
3. 产品真实：玩法、机制、UI、卖点和点击后第一步只来自商品分析；广告专用情节不得冒充游戏内真实节点。
4. 单一动作：每个方案固定一个 `coreGameplayVerb`。广告只展示阶段成功，不完整释放大招、解法或结局。
5. 留下缺口：结尾保留命运、能力、线索、资源或选择缺口，把完整闭环留给游戏和落地承接。
6. 角色不朗读功能说明；对白必须来自人物关系、冲突和交权窗口，CTA 不得破坏角色人设。

## 逐镜视听合同

每镜先写清 `触发事件 -> 镜头运动或剪辑动作 -> 终点构图 -> 信息/情绪结果`，再选择质量记录。至少核对：

- 构图与机位：主体位置、视线和头部留白、负空间、景深、焦点、屏幕安全区。
- 连续性：180°轴线、目线、动作方向、场景拓扑、人物/服装/道具、光源方向和色调不得无理由跳变。
- 运镜：必须由事件、人物行动或信息揭示触发；禁止无动机推拉摇移、无焦点漂移和用运动掩盖错误。
- 剪辑：每次切点都要增加信息、推进动作或改变情绪；闪回/闪前必须有触发点、时态区分和返回接点。
- 声音：片头优先用原剧声桥；人声可懂度最高；环境底噪保持空间；实体拟音先于 UI 反馈音；音乐留白服务台词和反应。
- 文字/UI：字幕、数字、Logo、按钮、落版和 CTA 使用确定性图层，禁止乱码、错译、错时序、溢出或遮挡核心表演。

`Under Crank` 指低拍摄帧率按标准帧率播放形成加速/跳步；`Over Crank` 指高拍摄帧率回放形成慢动作；后期插帧是生成中间帧；画质降级是分辨率、颗粒或扫描线等媒介处理。正式提示词使用这些规范定义，不沿用材料中的混淆命名。

## 导演风格转译

导演名只能用于检索。输出和生成提示词必须转译为构图、光线、色彩、镜头运动、剪辑、声音和表演等可观察参数：

1. 先查询完整记录并核对 `completeness_status` 与 `missing_fields`。
2. 只选 2-4 个真正服务本方案的辨识度元素，并逐项说明适用场景和叙事作用。
3. 可以跨导演按维度组合，但必须分维度说明来源与取舍；不得整体混合或只写“某导演风格”。
4. 原剧连续性、受众与生成成本优先；不复制具体作品、角色、剧情、构图序列或受保护的独特表达。
5. 摘要记录只使用实际提供字段；`not_provided` 和缺少的 5 位导演不得靠常识补齐。

## 质量判定

先判硬门，再判创作质量。任何硬门失败都输出 `blocker`，不能被平均分、审美评价、CTR 或 CVR 抵消。

| CQ | 判定 | 动作 |
|---|---|---|
| 0 | 连续性穿帮、人物 OOC、越轴、声画不同步、硬广台词、版权或合规风险之一成立 | 阻断，写整改方向与重新开门条件 |
| 1 | 无硬伤，叙事通顺，产品动作与承接可理解 | 可进入测试 |
| 2 | 情绪感染、视听执行和转化潜力明显高于基础要求 | 优先测试或放量，并记录变量和护栏 |
| 3 | 叙事、视听、表演、玩法融合和转化都具备可复用标杆价值 | 可沉淀为模板 |

硬门至少包括：无理由越轴或运镜、用转场遮错、人物 OOC、广告腔宣讲、无授权声纹克隆、UI 音效抢在实体动作前、粗暴插入录屏、完整释放结局/解法、结尾完全闭环、精确文字错误或遮挡表演。

## 子流程输出要求

策略候选为每个方案输出：

```json
{
  "audiovisualQuality": {
    "qualityRecordIds": ["DQ-014", "DQ-017", "DQ-111"],
    "directorReference": {
      "recordId": "DIR-005",
      "name": "大卫·芬奇",
      "translatedParameters": ["可观察参数 1", "可观察参数 2"]
    },
    "hardGateRisks": ["风险与证据缺口"]
  }
}
```

不需要导演参考时 `directorReference` 写 `null`。记录 ID 必须来自查询结果，不能编造；每个 ID 都要实际影响方案，不得为了数量堆叠。

制作草拟必须沿用已选方案的 `qualityRecordIds`，再按每镜真实需要补查构图、机位、运镜、剪辑、音频或 UI 记录。把规则编译到现有分镜字段 `camera`、`transition`、`audio`、`continuity` 和 `additionalNegativeConstraints`，不要把记录 ID 或导演姓名直接塞进视频生成提示词。若规则与原剧证据、商品事实或用户明确要求冲突，优先服从后者并在风险中说明取舍。
