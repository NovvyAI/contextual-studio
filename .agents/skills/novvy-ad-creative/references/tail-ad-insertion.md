# 片尾广告植入

产品候选已由用户提供或从 `novvy_list_products` 读取，参考视频已完成压缩解析后，使用本参考文件。`product_icon` 已从参考图组删除：产品 icon 不作为 GPT-image-2、参考图组、上传平台或最终视频模型输入；若产品对象包含 `iconUrl`，只视为平台元信息，不做必填、不上传、不传给后续生成模型。视频解析结果必须包含画风判断，用来决定普通 `imageUrls` 上传还是 Seedance `humanImageUrls` 真人上传。

## 策略

使用玩法凸出式植入：找到剧集中最强的类玩法特征，然后在片尾广告中延展同一种体验。广告应该像刚看完剧情后的自然奖励，而不是无关打断。

例子：

- 餐厅经营剧情：突出经营品类扩容、DIY 装修、快速赚钱循环、员工解锁、菜单升级和收入增长反馈。
- 家装或家庭冲突剧情：突出翻新、装饰自由、前后对比爽感、房间解锁和角色生活改善。
- 解谜或悬疑剧情：突出线索查找、反转揭示、关卡推进和“你能解开吗”的挑战感。
- 生存或资源匮乏剧情：突出资源管理、建造庇护所、风险收益选择和升级循环。
- 恋爱或关系剧情：突出剧情选择、造型、礼物系统、关系修复和情绪回报。

## 匹配规则

按证据评分，不按偏好猜测：

- 剧情玩法匹配：产品玩法与视频主题、可见任务或用户动机一致。
- 产品卖点匹配：产品描述中的可视化卖点能在所选内容时长内被观众理解。
- 受众匹配：剧集观众的情绪、兴趣、地区/语言约束与产品受众假设一致。
- 市场传达匹配：片尾广告能用一句清楚承诺接住商店/落地页，而不是只展示画面。
- 结尾连续性：广告能从最后一幕的情绪、物件、问题或未满足愿望自然进入。
- 情绪接续：广告第一镜延续原剧结尾情绪，再把情绪转成游戏玩法期待。
- 玩法可视化：产品描述里有能在当前逐镜计划内展示清楚的具体功能。
- 用户情绪连续：观众在结尾的情绪能自然接住产品承诺。
- 转化率实现方式：明确注意力承接、爽点展示、点击理由、下载/试玩理由和 CTA。
- 风险：避免只靠弱关键词、低置信视频证据或产品描述没有支持的卖点。

优先选择 `description` 明确支撑广告角度的产品。少于 3 个可行匹配时，可以少给选项并说明原因。

## 推荐表

只返回 3-4 个选项。使用紧凑 Markdown 表格，然后直接请用户选择一个或多个编号。用户多选时，后续每个选项作为独立方案并行推进。

必需列：

- `编号`：稳定选项 ID，如 A/B/C/D。
- `产品`：来自 MCP 的产品名。
- `视频匹配点`：支持匹配的剧情玩法或结尾线索。
- `片尾广告角度`：片尾要插入什么类型的广告。
- `玩法卖点`：要强化的具体卖点。
- `受众`：目标观众和动机。
- `市场传达`：一句话承诺或广告口径。
- `情绪接续`：原剧结尾情绪如何过渡到游戏期待。
- `转化实现`：点击/下载/试玩动机和 CTA 方式。
- `片尾进入方式`：原视频结尾如何转入广告。
- `可变内容时长与节奏`：根据叙事和玩法闭环所需信息量给出建议范围，不默认或固定为 12 秒；最终内容时长由逐镜时长决定，落版另计。
- `推荐理由`：一句话说明为什么优先选。
- `风险/需确认`：不确定点、缺失信息或品牌安全风险。

表格后询问用户选择一个或多个编号，或说明要改哪个产品/广告角度。用户选择前，不生成落版图、不上传参考图、不创建最终 MCP payload。

## 选择后

用户选择一个或多个选项后，生成简洁创意方案和参考图组规划。若用户多选，主流程为每个已选编号启动独立 subagent 并行执行后续创意、落版图、参考图组上传和视频提示词准备；每个 subagent 只能处理自己负责的编号，不共享长上下文。

参考图组只聚焦：

- 男主人公和女主人公的正视图、侧视图，以及与视频结尾的关系。
- 人物身份一致性：脸部、发型、年龄感、体型、服装风格和身份气质必须基于原视频截图保持一致。
- 产品呈现：只使用产品名、英文利益点、英文 CTA 和商店/落地页承接表达品牌与转化，不引入产品 icon 作为素材。
- 审核通过的落版图：由 GPT-image-2 先生成并经用户确认后，作为 `final_card` 槽位进入参考图组。
- 片尾广告中需要保持的背景、道具和玩法视觉符号，用文字写入后续视频提示词，不再用图片模型做九宫格样例图。

参考图组默认方式：

- 数量：5 张独立图片，按槽位顺序传入最终视频 payload，不拼成单张图。
- 来源：视频解析子流程截取或选定的 `male_front`、`male_side`、`female_front`、`female_side`，以及审核通过的 `final_card`。
- 方式：使用原始截图和审核通过的落版图；人物截图只做必要裁切、缩放或留白，不用图片模型重绘人物。
- 上传：本地文件批量 HTTP 直传必须交给独立上传 subagent；父流程必须传入 `SKILL_DIR`，subagent 先运行 `NOVVY_PYTHON_BIN="$("$SKILL_DIR/scripts/novvy_python.sh")"`，再运行 `"$NOVVY_PYTHON_BIN" "$SKILL_DIR/scripts/upload_ai_platform_asset.py"`，用重复的 `--slot SLOT=SOURCE` 显式传入槽位，不得调用 `novvy_upload_asset`，默认不得运行 `scripts/compose_reference_panel.py`。
- 视频引用：普通上传把多张 URL 数组放入 `imageUrls`；真人写实且使用 Seedance 真人上传时把多张 `asset://...` 数组放入 `humanImageUrls`。

如果没有可用男女主人公正/侧视图，不要进入视频生成；若用户已经提供本地视频路径、视频附件或可分析的视频 URL，由视频解析子流程直接抽取/选择关键帧，不需要用户确认。若仍缺失，再让用户提供人物截图或关键帧 URL。若只能找到最接近的替代角度，必须标明风险并等待用户确认。缺少产品 icon 不是阻塞项，因为 `product_icon` 不再参与参考图组、上传或生成。

## GPT-image-2 落版图

生成参考图组前，先展示 GPT-image-2 落版图生成审核。审核内容只包含：

- GPT-image-2 落版图提示词。
- 为什么这样生成：说明该提示词如何服务产品卖点、CTA 可读性、品牌一致性和最后一镜承接。

不要向用户展示完整图片 MCP payload。GPT-image-2 实际 `prompt` 必须用英文，所有落版图可见文字、利益点和 CTA 都必须是英文；中文只用于给用户解释生成理由。用户确认后才能调用 `novvy_create_image_generation`。需要确认时，如果当前工具列表中存在可用的 `request_user_input`，并且当前协作模式/系统规则允许调用它，主 agent 必须用 `request_user_input` 弹出 Codex 原生确认框；如果该工具不存在、被当前模式拒绝或返回空答案/取消，不得继续调用消耗型 Novvy 工具，必须说明当前线程没有可用的原生确认工具并停止等待用户回复。查询到结果后展示落版图 URL，并用 Markdown 链接展示为网页跳转，例如 `[落版图预览](<结果URL>)`；不要把远程结果 URL 放进图片 Markdown 里渲染。后续 `final_card` 槽位可直接使用该结果 URL；只有用户要求本地保存或远程 URL 无法用于后续上传时，才运行 `download_result_asset.py` 保存本地副本。让用户审核通过或提出修改；未通过时按反馈生成新版英文 GPT-image-2 提示词和修改理由，确认后重新生成。只有落版图审核通过后，才能进入参考图组批量上传。

## 参考图组上传

展示“参考图组上传执行说明”。说明内容包含：

- 参考图组槽位表：`male_front`、`male_side`、`female_front`、`female_side`、`final_card`。
- 每个槽位的来源路径或 URL、可见特征、置信度和替代风险。
- 画风判断和上传模式：`cartoon_animation` 使用普通 asset 上传并写入 `imageUrls`；`live_action_realistic` 使用 Seedance 真人上传并写入 `humanImageUrls`；`mixed_unknown` 向用户说明风险，默认使用普通 asset 上传并写入 `imageUrls`，不要为了上传模式额外等待确认。
- 将交给上传 subagent 的任务规格。
- 将由上传 subagent 执行的 `"$NOVVY_PYTHON_BIN" "$SKILL_DIR/scripts/upload_ai_platform_asset.py"` 参数；一次用 `--slot "slot=<路径或URL>"` 传入全部槽位来源，只展示模式、模型和文件路径，不展示 token、签名 URL、凭据、`dataUrl` 或 `base64`，这些只能以占位符出现。
- 上传脚本会在 HTTP 上传前校验图片宽度是否在 300-6000px；若返回 `failedStep: "image_validation"`，先替换、重新裁切、补边或放大对应槽位图片，不要继续生成视频 payload。

展示执行说明后，不要等待用户确认；直接读取 `local-upload-subagent.md`，启动独立上传 subagent。subagent 运行 HTTP 直传脚本批量上传多张参考图。不要让用户手动补 URL。不要调用 `novvy_upload_asset`。不要生成九宫格样例图或单张拼接图。上传成功后，subagent 只能把脚本默认精简 JSON 中的 `referenceField`、`referenceUrls`、`videoPayloadHint`、`slots`、`skippedSlots`、`fileNames` 和告警返回主流程；不得返回 token、签名 URL、base64、完整 `assets`、完整脚本原始输出或 MCP raw 内容。若脚本顶层缺少 `referenceField`，或 `videoPayloadHint[referenceField]` 不是完整数组，不得返回 `unavailable` 或自动重传，必须按 `local-upload-subagent.md` 的 `http_upload_parse` 失败处理。主流程只把完整的 `videoPayloadHint[referenceField]` 数组放入对应的视频字段。

上传完成后展示 `referenceUrls`、`referenceField` 和槽位映射；不要直接展开签名 URL、完整脚本输出或真实 asset 调试信息。随后展示一一对照 UI 槽位表：每行包含槽位名、槽位图片或来源、上传后引用摘要、可见特征/品牌要点、将写入视频提示词的一致性用途。让用户确认是否进入视频提示词，或用槽位名指定替换。

如果某个槽位不合适：

- 用户用槽位名指出修改方向，例如 `male_side` 或 `final_card`。
- 未点名槽位保持不变。
- 重新启动上传 subagent 批量上传替换后的完整参考图组。
- 继续使用新的 `referenceUrls` 和 `referenceField`，不得切回 MCP 上传或单图引用。
- 再次展示 `referenceUrls`、`referenceField` 和槽位图片/提示词一一对照表，让用户确认是否进入视频提示词。

## 视频提示词

用户选择文字分镜后，先为每一镜生成并审核 9:16 分镜草案图。每张图片必须是一张完整电影感关键帧，不得生成拼贴、九宫格、带镜号边框或解释文字的 storyboard sheet。人物镜使用已确认人物图保持身份、服装和配饰一致；末镜使用已确认落版图保持英文产品文案和 CTA。支持单镜按意见重新生成；只有用户统一确认整组分镜图后才进入视频提示词。

参考图组通过后，直接生成最终片尾广告视频提示词，不输出“Memory 总结”。工作台允许用户在最终视频生成时选择 `Novvy MCP` 或 `ImaRouter`。两种方式都按镜头序号绑定参考：每个镜头只使用同序号的已确认分镜图作为第一主参考，并附加全部已确认人物正/侧面图；前者约束构图与动作，后者约束人物身份一致性。Novvy MCP 使用 `seedance-2.0-fast`，当前分镜图放入 `imageUrls`，人物图放入 `humanImageUrls`；ImaRouter 使用 `seedance-2.0`，参考数组为当前分镜图在前、人物图在后。不得把整组分镜图无差别传给每个镜头。公网图直接走 ImaRouter asset 审核；本地短剧截图必须先上传到配置的 GCS 公网桶，再走同一 asset 审核，最终只提交 `asset://...`，不得发送 base64 图片。

默认内部设置：

- `model`: `seedance-2.0-fast`
- `ratio`: `9:16`
- `duration`: `15`
- `resolution`: `720p`
- `generateAudio`: `true`
- `storyboardCount`: 不超过 `3`
- 参考图：根据上传模式传入多张参考图数组；普通上传用 `imageUrls`，Seedance 真人上传用 `humanImageUrls`。不要只传第一张，也不要把多张图合成单张面板后传入。
- 最后一镜必须生成落版图，占最后 2-3 秒，包含产品名、英文核心利益点、英文下载/试玩 CTA，以及 App Store/Google Play 或落地页承接信息。落版图必须干净可读，不能遮挡人物脸。

视频生成审核分为两份文本：用户可见的中文审核稿，以及实际提交给模型的英文 `prompt`。中文审核稿必须按固定中文结构展示，结构清晰、字段完整、花括号只作为编写占位，不得原样输出；允许在【视频生成目标】中写时长和画幅，例如“生成一支 15 秒、9:16 真人写实短视频”。实际写入 `novvy_create_video_generation.prompt` 的文本必须是该中文审核稿的等义英文翻译稿，不得提交中文提示词。中文审核稿和英文提交稿都不得写真实图片 URL、`720p`、`generateAudio`、`imageUrls`、`humanImageUrls`、`ratio`、`duration`、`resolution` 或模型名。示例模板中的业务内容要按当前广告方案替换；不要照抄“不要品牌 logo”“不要字幕”等会与英文 CTA、英文落版图文字冲突的负面约束，除非用户明确要求。

调用 `novvy_create_video_generation` 时，payload 必须使用英文 `prompt` 承载完整分镜，最后一个分镜必须写清英文落版图文案；使用 `model: "seedance-2.0-fast"`、`ratio: "9:16"`、`duration: 15`、`resolution: "720p"`、`generateAudio: true`。如果 `referenceField` 是 `imageUrls`，把 `videoPayloadHint.imageUrls` 的完整数组写入 `imageUrls`；如果 `referenceField` 是 `humanImageUrls`，把 `videoPayloadHint.humanImageUrls` 的完整数组写入 `humanImageUrls`，不要同时重复放进 `imageUrls`。数组顺序必须保持上传 subagent 返回的 `slots` 顺序；普通 `imageUrls` 默认顺序为 `male_front`、`male_side`、`female_front`、`female_side`、`final_card`，Seedance `humanImageUrls` 只包含实际上传的人像槽位，不包含 `final_card` 或 `product_icon`。

视频提示词必须说明参考图槽位顺序，并使用“由视频参考图字段按顺序传入的多张参考图”这类说法，不写具体 URL。中文审核稿分镜最多 3 个，每个分镜写清视觉动作、镜头/运动、玩法卖点、英文屏幕文字和英文音频/对白提示；最后分镜必须明确沿用审核通过的英文落版图元素。英文提交稿必须逐段保留同样约束，并明确 all on-screen text, spoken dialogue, voiceover, CTA, and final card copy are in English only. 真人写实时写“真人写实短视频”，卡通动画时按画风判断替换为对应风格，不要与参考视频画风冲突。中文审核稿用镜 1/镜 2/镜 3 表达顺序。

最终视频提示词必须按以下结构清晰展示给用户，但这份中文结构只作为审核稿，不直接作为 `prompt` 提交。确认后必须把同样内容逐段翻译成英文，作为 `novvy_create_video_generation.prompt` 的实际值。

{用 1-3 句写清情绪如何从原剧结尾过渡到玩法爽感、奖励期待或 CTA}

【分镜脚本】

剧情功能：{这一镜在叙事中的作用}

一致性要求：女主/男主必须严格保持参考图身份一致。

## 视频复审和二次修改

任一视频供应商返回真实视频后，先在后端完成确定性落版拼接：完整保留本次逐镜计划生成的内容视频，再将审核通过的原始 `final_card` 制作成配置时长的静态片段追加到结尾。不得让视频模型重绘最终产品名、利益点、商店承接或 CTA；内容音轨完整保留，落版段补静音。用户复审卡展示拼接后的成片，同时保留供应商原任务 ID 供追踪。

视频生成完成并查询到结果后，不要默认结束。展示视频任务 ID、结果 URL 的 Markdown 网页跳转链接、版本号、模型、参考图组引用摘要、`referenceField`、比例、时长、分辨率、音频设置和简短生成摘要，然后询问用户是否通过；不要在对话中嵌入远程视频。

如果用户确认通过，结束流程。

如果用户要求修改：

- 把用户反馈整理成“修改摘要”，按时间段、分镜或元素分类，例如人物动作、镜头节奏、字幕、声音、落版图、CTA。
- 新建一个版本号，例如从 `V1` 递增到 `V2`；不要声称能直接编辑原任务。
- 默认沿用已确认产品、参考图组引用、`referenceField`、人物一致性规则、已通过落版图、品牌安全限制和固定视频参数，除非用户明确要求变更。
- 如果只改视频画面、节奏、字幕、声音、落版文案或 CTA，继续使用原参考图组引用；若改落版图卡面，先回到 GPT-image-2 落版图审核并重新批量上传参考图组。
- 如果用户要求换人物截图或参考图组，先回到参考图组上传流程，通过上传 subagent 得到新的 `referenceUrls` 和 `referenceField`，再生成新版视频提示词和内部调用参数。
- 如果用户要求换模型，说明当前 plugin 只支持 `seedance-2.0-fast`，不提供模型切换。
- 展示修改摘要、沿用/变更项、新版本中文审核提示词、模型、时长、比例和分辨率，优先通过可用的 `request_user_input` 等待用户明确确认后再提交；提交时仍把中文审核稿等义翻译成英文 `prompt`，并保持所有生成文字和声音为英文。不要展示完整 `novvy_create_video_generation` payload。
- 新任务完成后再次进入视频复审，直到用户确认通过。
